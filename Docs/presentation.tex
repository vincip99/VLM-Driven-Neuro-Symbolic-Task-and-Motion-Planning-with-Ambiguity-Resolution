\begin{frame}
    \frametitle{VLM Training methodologies}
    It is the mechanism that allow fusing information from both vision and language encoders so to correlate images with text and make decision on the 2 modalities togheter:
    \begin{itemize}
        \item Contrasive learning: uses joint or shared embedding space. The VLM is trained on datasets of image-text pairs and learns to minimize the distance between embeddings of matching pairs and maximize it for nonmatching pairs.
        \item Masking: models learn to predict randomly obscured parts of an input text or image.
        \item Generative model training: entails learning to generate new data
        \item Pretrained models: A pretrained LLM and a pretrained vision encoder can be used, with an added mapping network layer that aligns or projects the visual representation of an image to the LLM’s input space.
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{Symbolic planning in PDDL}
    A planning Problem is defined by:
    \begin{itemize}
        \item \textbf{Predicates}: Set of grounded states
        \item \textbf{Actions}: Set of possible moves, defined by preconditions and effects.
        \item \textbf{Planning Language} $\mathcal{L}$: the set af all possible predicates and variables.
        \item \textbf{Planning Domain} $\mathcal{D} = (\mathcal{L}, A)$: containing the set of usable predicates (states) and usable actions
        \item \textbf{Planning Problem} $\mathcal{P} = (\mathcal{D}, I, G)$: build with the domain and the set of initial states (or initial predicates) and the set of goal states (or goal predicates)
    \end{itemize}

    \textbf{PDDL}, stands for Planning Domain Definition Language, is the gold standards for Classical AI Planning. To solves The planning problem, two main approaches are possible: \textbf{State Space Search} and \textbf{Plan Space Search}.

    To solve the Planning Problem \textbf{Fast Downward} has been used. It is an Heuristic Forward-Chaining State-Space Planner.
\end{frame}

\begin{frame}
    \frametitle{Executive Layer: Behavior Trees}
    \begin{columns}[T]
        % Left Column: Text and Definitions
        \begin{column}{0.55\textwidth}
            \small
            \begin{itemize}
                \item A \textbf{Behavior Tree} is a directed tree with nodes classified as root, control flow, or execution (tasks).
                \item Execution starts from the root, which sends \textit{ticks} to its children at a set frequency.
                \item A node returns one of three statuses: \textbf{Running}, \textbf{Success}, or \textbf{Failure}.
            \end{itemize}
            
            \vspace{0.3cm}
            
            \setbeamercolor{verdictbox}{bg=darkblue,fg=white}
            \begin{beamercolorbox}[sep=4pt,shadow=true,rounded=true]{verdictbox}
                \centering \textbf{Control Flow Nodes} \\
                \vspace{0.1cm}
                \raggedright
                \footnotesize
                \begin{itemize}
                    \setlength\itemsep{0.3em}
                    \item \textbf{Selector:} A fallback node that executes the first child that does not fail. Returns \textbf{Success} or \textbf{Running}.
                    \item \textbf{Sequence:} Executes children in order until one succeeds. Returns \textbf{Failure} or \textbf{Running} immediately if a child fails or is still running.
                \end{itemize}
            \end{beamercolorbox}

\frametitle{BT Builder: Parsing and Sequence Compilation}
\begin{columns}[T]
    \begin{column}{0.53\textwidth}
        \small \textbf{1. Parsing PDDL Plan (\texttt{parse\_pddl\_action})}
        \scriptsize
        Cleans raw planner text into structured Python data:
        \begin{itemize}
            \item \textbf{Filters Clutter}: Discards comments starting with \texttt{;} (e.g., \texttt{; cost = 2}) and blank lines.
            \item \textbf{Strips Planner Syntax}: Removes step prefixes (e.g., \texttt{0:}) and outer parentheses \texttt{(...)}.
            \item \textbf{Extracts Tokens}: Normalizes action name to lowercase and collects arguments:
            \begin{center}
                \tiny \texttt{"0: (place yellow\_cube pot)"} $\;\longrightarrow\;$ \texttt{("place", ["yellow\_cube", "pot"])}
            \end{center}
        \end{itemize}

        \vspace{0.15cm}
        \small \textbf{2. Plan to Sequence (\texttt{pddl\_plan\_to\_sequence})}
        \scriptsize
        Converts the parsed action list into an executable Behavior Tree Sequence:
        \begin{itemize}
            \item \textbf{Skill Dispatch}: Uses \texttt{SKILL\_REGISTRY} to map actions to robot skills (\texttt{"pick"}, \texttt{"place"}).
            \item \textbf{Argument Binding}: Passes simulator environment and object targets (\texttt{object}, \texttt{asset}).
        \end{itemize}

\begin{frame}[fragile]
\frametitle{BT Builder: Goal Checking and Reactive Tree Generation}
\begin{columns}[T]
    \begin{column}{0.53\textwidth}
        \small \textbf{3. Goal-Guarded Wrapper (\texttt{wrap\_with\_goal\_check})}
        \scriptsize
        A plain sequence is open-loop. If an object drops, it fails blindly. We wrap it in a reactive fallback loop:
        \begin{itemize}
            \item \textbf{Pre-Check (\texttt{GoalCheck\_Pre})}: Verifies if goal is already met before moving. If yes $\to$ succeeds immediately (no redundant actions).
            \item \textbf{Selector (\texttt{memory=False})}: Re-evaluates continuously on every tick for dynamic preemption.
            \item \textbf{Post-Check (\texttt{GoalCheck\_Post})}: Confirms physical completion after the sequence finishes.
            \item \textbf{Retry Loop (\texttt{Retry})}: If the grasp slips and post-check fails, automatically retries the plan up to $N$ times.
        \end{itemize}

        \vspace{0.15cm}
        \small \textbf{4. Main Entrypoint (\texttt{build\_bt\_from\_pddl\_plan})}
        \scriptsize
        Single builder API providing two execution modes:
        \begin{itemize}
            \item \texttt{wrap\_goal\_check=False}: Raw Sequence (open-loop baseline).
            \item \texttt{wrap\_goal\_check=True}: Self-healing tree with retry loop.
        \end{itemize}
    \end{column}

    \begin{column}{0.47\textwidth}
        \setbeamercolor{treebox}{bg=gray!10,fg=black}
        \begin{beamercolorbox}[sep=5pt,rounded=true,shadow=true]{treebox}
            \scriptsize \textbf{Goal-Guarded Tree Architecture}
            \tiny
            \begin{verbatim}
[?] goal_guarded_root (Selector)
 |-- [>] GoalCheck_Pre (already met?)
 `-- [R] retry_until_goal (max=10)
      `-- [->] attempt (Sequence)
           |-- [->] pddl_plan_sequence
           |    |-- PickUp(yellow_cube)
           |    `-- PlaceInBin(yellow_cube->pot)
           `-- [>] GoalCheck_Post (verified?)
            \end{verbatim}
        \end{beamercolorbox}

        \vspace{0.12cm}
        \setbeamercolor{verdictbox}{bg=darkblue,fg=white}
        \begin{beamercolorbox}[sep=4pt,shadow=true,rounded=true]{verdictbox}

\begin{frame}[fragile]
    \frametitle{Path Planning: RRT}
    Rapidly Random Trees (RRT) is a Probabilistic Path Planning method used to efficiently construct a path in continuous spaces.
    \begin{algorithm}[H]
        \captionsetup{font=scriptsize}
        \scriptsize
        \caption{Goal Oriented RRT Algorithm}
        \begin{algorithmic}[1]
            \State $G.\text{init}(x_{\text{start}})$
            \For{$i = 1 \dots K$}
                \State $p = \text{UniformRandom}(0, 1)$ 
                \If{$p \leq p_{\text{goal}}$}
                    \State $x_{\text{rand}} \gets x_{\text{goal}}$
                \Else
                    \State $x_{\text{rand}} \gets \text{RandPose}()$
                \EndIf
                \State $x_{\text{nearest}} \gets \text{NearestVertex}(x_{\text{rand}}, G)$
                \State $x_{\text{new}} \gets \text{NewConf}(x_{\text{nearest}}, x_{\text{rand}}, \Delta x)$
                \If{\text{CollisionFree}$(x_{\text{nearest}}, x_{\text{new}})$}
                    \State $G.\text{add\_vertex}(x_{\text{new}})$
                    \State $G.\text{add\_edge}(x_{\text{nearest}}, x_{\text{new}})$
                    \If{$x_{\text{new}} \in X_{\text{goal}}$}
                        \Return \text{Path Found}
                    \EndIf
                \EndIf
            \EndFor
            \State \Return $G$
        \end{algorithmic}
    \end{algorithm}
    The goal oriented version samples the goal point with a given probability $p$ while a random point with probability $1-p$. 
\end{frame}

\begin{frame}
    \frametitle{Trajectory Tracking}
    \begin{itemize}
        \item \textbf{Cartesian Setpoints:} 
        The waypoints generated by the task-space RRT are Cartesian poses used as setpoints for a \textbf{Proportional (P) Controller}.
        \item \textbf{Tracking Error:} 
        At each time step, the position error is defined as:
        \[
            \mathbf{e} = \mathbf{p}_{\text{target}} - \mathbf{p}_{\text{EF}}
        \]
        \item \textbf{Control Law:} 
        The controller outputs velocity commands bounded by a maximum speed:
        \[
            \mathbf{v}_{\text{cmd}} = \operatorname{clip}(K_p \mathbf{e},\, -v_{\max},\, v_{\max})
        \]
        which are sent to the underlying operational space controller.
        \item \textbf{Application:} 
        Used specifically during the \textbf{approach phase} in the pick action and during the \textbf{place action}. The place skill itself is completely based on the RRT planner and the trajectory tracker, while the pick skill is composed by more modules and need further explaination.
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{Manipulation: Heuristic Approach}
    \small Consists of a \textbf{Staged FSM}, that executes the following phases:
    \begin{columns}
        \begin{column}{0.5\textwidth}
            \footnotesize
            \begin{enumerate}
                \item \textbf{RRT Planning:}
                Traverse collision-free waypoints to hover pose (\texttt{== end\_pose}).
                
                \item \textbf{Descent Phase:}
                Descend vertically until reaching grasp height (\texttt{z $\le$ z\_tol}).   
            \end{enumerate}
        \end{column}

        \begin{column}{0.5\textwidth}
            \footnotesize
            \begin{enumerate}
                \item[3.] \textbf{Grasp Phase:}
                Actuate gripper firmly for set duration (\texttt{t > t\_grasp}).
                
                \item[4.] \textbf{Lift Phase:}
                Elevate object to safe height to verify pick. If it fails, it will retry from the Descent phase.
            \end{enumerate}
        \end{column}
    \end{columns}

\begin{frame}
    \frametitle{Proximal Policy Optimization}
    Proximal Policy Optimization is an on-policy actor-critic Reinforcement Learning method. PPO updates policy parameters $\theta_{k+1}$ by maximizing the \textbf{Clipped Surrogate Objective}:
    \[
    L^{\text{CLIP}}(\theta) = \hat{\mathbb{E}}_t \left[ \min \left( r_t(\theta)\hat{A}_t, \; \operatorname{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t \right) \right]
    \]
    
    where the probability ratio is defined as:
    \[
    r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_k}(a_t \mid s_t)}
    \]

    \begin{itemize}
        \item \textbf{Clipped Objective:} The hyperparameter $\epsilon \approx 0.2$ penalizes moving $r_t(\theta)$ outside $[1-\epsilon, 1+\epsilon]$, preventing destructively large policy updates.
        \item \textbf{Actor-Critic Architecture:} Jointly optimizes a policy network $\pi_\theta(a|s)$ and a state-value baseline $V_\phi(s)$ using Generalized Advantage Estimation (GAE).
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{Manipulation: PPO Approach}
    \small
    \texttt{TaskSpaceRRT} provides coarse global navigation to a pre-grasp hover pose ($\sim 18\,\text{cm}$ above the object). The \textbf{PPO policy} then takes over using a minimal, translation-invariant \textbf{11D observation vector}:
    
    \vspace{0.15cm}
    \centering
    $\mathbf{o}_t = \Big[\; \underbrace{\Delta\mathbf{p}}_{\mathbb{R}^3},\;\; \underbrace{\mathbf{q}_{\text{grip}}}_{\mathbb{R}^2},\;\; \underbrace{\dot{\mathbf{q}}_{\text{grip}}}_{\mathbb{R}^2},\;\; \underbrace{z_{\text{rel}}^{\text{EEF}}}_{\mathbb{R}^1},\;\; \underbrace{\Delta z_{\text{obj}}}_{\mathbb{R}^1},\;\; \underbrace{c_{\text{grasp}}}_{\{0,1\}},\;\; \underbrace{m_{\text{geom}}}_{\{0,1\}} \;\Big]^\top \in \mathbb{R}^{11}$
    \vspace{0.2cm}
    \begin{columns}[T]
        \begin{column}{0.48\textwidth}
            \begin{block}{Kinematics \& Spatial Relations}
                \begin{itemize}\footnotesize
                    \item $\Delta\mathbf{p} = \mathbf{p}_{\text{obj}} - \mathbf{p}_{\text{EEF}}$: 3D relative vector (translation invariance across table).
                    \item $z_{\text{rel}}^{\text{EEF}} = p_{\text{EEF}, z} - z_{\text{table}}$: Table clearance to avoid surface collisions.
                    \item $\Delta z_{\text{obj}} = p_{\text{obj}, z} - p_{\text{obj}, z}^{(0)}$: Vertical displacement measuring lift progress.
                \end{itemize}
            \end{block}
        \end{column}
        \begin{column}{0.48\textwidth}
            \begin{block}{Gripper State \& Morphology}
                \begin{itemize}\footnotesize
                    \item $\mathbf{q}_{\text{grip}}, \dot{\mathbf{q}}_{\text{grip}}$: Left/right finger joint positions and velocities (contact stall detection).
                    \item $c_{\text{grasp}} \in \{0, 1\}$: Bilateral force-closure flag (Robosuite contact normal check).
                    \item $m_{\text{geom}} \in \{0, 1\}$: Shape token ($0$: cube, $1$: can) enabling multi-geometry conditioning.
                \end{itemize}
            \end{block}
        \end{column}
    \end{columns}
\end{frame}

\begin{frame}{Manipulation: Shaped Reward Formulation}
    \small
    The agent is trained with a multi-stage continuous-discrete reward guiding the transition from approach $\to$ grasp $\to$ lift:
    \begin{equation*}
        R_t = r_{\text{reach}} + r_{\text{grip}} + r_{\text{grasp}} + r_{\text{lift}} - c_{\text{step}} + r_{\text{terminal}}
    \end{equation*}
    \vspace{-0.2cm}
    \begin{columns}[T]
        \begin{column}{0.50\textwidth}
            \begin{block}{Continuous Shaping Terms}
                \begin{itemize}\scriptsize
                    \item \textbf{Smooth Reaching ($d = \|\Delta\mathbf{p}\|_2$):}
                    \newline $r_{\text{reach}} = 1.0 - \tanh(10.0 \cdot d)$
                    \item \textbf{Grasp Maintenance:}
                    \newline $r_{\text{grasp}} = 2.0 \cdot \mathbb{I}(\text{grasped})$
                    \item \textbf{Conditioned Vertical Lift:}
                    \newline $r_{\text{lift}} = 20.0 \cdot \max(0, \Delta z_{\text{obj}}) \cdot \mathbb{I}(\text{grasped})$
                    \newline \textit{(Avoids lifting with an empty gripper)}
                    \item \textbf{Alive Cost:} $c_{\text{step}} = 0.01$ (incentivizes speed)
                \end{itemize}
            \end{block}
        \end{column}
        \begin{column}{0.48\textwidth}
            \begin{block}{Action Shaping \& Terminals}
                \begin{itemize}\scriptsize
                    \item \textbf{Gripper Timing Incentive $r_{\text{grip}}$:}
                    $$r_{\text{grip}} = \begin{cases}
                        +0.5 & \text{if } d < 4\,\text{cm} \land a_g > 0 \\
                        -0.25 & \text{if } d < 4\,\text{cm} \land a_g \le 0 \\
                        -0.2 & \text{if } d \ge 4\,\text{cm} \land a_g > 0.2 \\
                        0 & \text{otherwise}
                    \end{cases}$$
                    \textit{Prevents premature closure before alignment.}
                    \item \textbf{Terminal Sparse Rewards:}
                    \newline $+15.0$ if $\Delta z_{\text{obj}} \ge 6\,\text{cm} \land \text{grasped}$ (\textbf{Success})
                    \newline $-2.0$ if $p_{\text{obj}, z} < z_{\text{table}} - 4\,\text{cm}$ (\textbf{Drop})
                \end{itemize}
            \end{block}
        \end{column}
    \end{columns}
\end{frame}

                    \item \textbf{Privileged vs Reactive:} Heuristic requires exact object coordinates; PPO relies only on local $\Delta\mathbf{p}$ and joint kinematics.
